# Адаптации сайта под устройства

Здесь лежит всё, что **отличается** между устройствами: стили уровней, мобильные компоненты и логика.
Общие компоненты остаются в `features/`, `shared/`, `pages/` и описывают базовую (десктопную) версию;
папки адаптаций хранят только отличия — проект не дублируется под каждое разрешение.

## Уровни (брейкпоинты)

| Уровень   | Ширина    | Что меняется                                                                                                         |
| --------- | --------- | -------------------------------------------------------------------------------------------------------------------- |
| `mobile`  | < 768     | своя навигация (кнопки «лого» и «меню» + полноэкранное меню), карта на весь экран со шторкой снизу, модалки — шторки |
| `tablet`  | 768–1199  | таб-бар сверху; стоя — компактная раскладка (как телефон), лёжа (1024–1199) — боковая панель и строка фильтров       |
| `desktop` | 1200–1919 | полная композиция; до 1439 — уже панель дашборда                                                                     |
| `full-hd` | 1920–2559 | шире панели карты и колонка текстовых страниц                                                                        |
| `2k`      | 2560–3839 | корневой шрифт 20 px (×1,25) — если экран не ниже 1200 px                                                            |
| `4k`      | ≥ 3840    | корневой шрифт 28 px (×1,75) — если экран не ниже 1800 px                                                            |

Числа — в `core/breakpoints.js` (JS) и повторены в медиа-запросах CSS (CSS не умеет импортировать
переменные в `@media`). Брейкпоинты стоят там, где интерфейс реально начинает ломаться: например,
главная переходит на вертикальную раскладку с 1024, а не с 768 — в портретном планшете город и форма
рядом не помещаются.

## Компактная раскладка

Телефоны, планшеты стоя до 1023 px **и любой портретный экран уже 1200 px** (iPad Pro стоя — 1024 × 1366)
получают «компактную» раскладку: карта со шторкой, главная, поддержка и «О проекте» — в одну колонку.
Рядом (город + вход, карта + панели) — только на альбомном экране от 1024 px. Условие одно:
`isCompact(width, height)` в JS и `(max-width: 1023px), (orientation: portrait) and (max-width: 1199px)` в CSS.

## Контейнерные запросы

Панели, которые живут и в боковой панели, и в шторке (карточка района, дашборд, таблица районов), подстраиваются
под **свою** ширину через `@container` в модуле компонента — это свойство компонента, а не устройства.

## Почему 2K и 4K — через корневой шрифт

Все размеры интерфейса (отступы, радиусы, шрифты, высоты кнопок, ширины панелей) заданы в `rem`
(токены `styles/tokens.css`). Уровень поднимает `font-size` у `:root` — и весь интерфейс растёт
пропорционально, сохраняя композицию Full HD (≈ 2000–2200 px по ширине). Интерфейс не растягивается на
весь экран: ширина текстовых страниц ограничена `--content-max`. Условие по высоте не даёт раздуть
интерфейс на ультрашироких мониторах (2560 × 1080 остаётся в масштабе Full HD).

Код, который рисует в пикселях (SVG-графики, холсты), умножает свои размеры на `rootScale()`.

## Структура

```
adaptations/
├── index.css            # подключает все файлы уровней; импортируется ПОСЛЕДНИМ в main.jsx
├── core/                # логика — можно импортировать из любого слоя (как shared/)
│   ├── breakpoints.js   # уровни, usesSheet(width) — где карта использует шторку
│   ├── useViewport.js   # хук: tier, isMobile, sheet, coarse — для смены СТРУКТУРЫ, не стилей
│   ├── renderQuality.js # качество WebGL/canvas: плотность пикселей, бюджет пикселей, частицы, детализация
│   └── rootScale.js     # во сколько раз интерфейс крупнее базового (2K/4K)
├── desktop/
│   ├── desktop.css      # 1200–1919: узкие ноутбуки
│   ├── home.css         # главная на низких экранах (≤ 820 px высоты)
│   ├── full-hd/         # токены Full HD
│   ├── 2k/              # масштаб 2K
│   └── 4k/              # масштаб 4K
├── tablet/              # tablet.css (токены), navigation, home, map, stats, support, about
├── touch/touch.css      # сенсорные экраны при любой ширине (pointer: coarse): цели не меньше 44 px
└── mobile/
    ├── mobile.css       # токены телефона (читаемые подписи)
    ├── home|map|forms|modal|support|about.css
    ├── navigation/      # MobileNav — логотип и меню вместо таб-бара, полноэкранное меню
    ├── sheet/           # BottomSheet — шторка с тремя положениями (peek / half / full)
    └── map/             # FilterChip (фильтры в чипе → шторка), MapFab («+» и «весь город»)
```

## Как это подключено

- **Стили уровней** переопределяют стили компонентов через атрибут `data-ui` на элементе:
  `<aside className={styles.panel} data-ui="map-panel-left">` → в `tablet/map.css`
  `:root [data-ui='map-panel-left'] { … }`. `:root` поднимает специфичность, а подключение
  `index.css` последним — порядок; поэтому правило уровня побеждает базовое.
- **Смена структуры** (другой компонент, а не другие стили) — через `useViewport()`:
  `App` показывает `MobileNav` вместо `TabBar`, `MapPage` — шторку вместо боковых панелей.
- **3D** берёт качество из `renderQuality()` (`SceneRuntime`, фон сайта, частицы главной, жители в истории).

## Правила

- Базовые стили компонента описывают десктоп; медиа-запросов по ширине в модулях компонентов нет —
  они здесь. Исключение — `prefers-reduced-motion` (это настройка доступности, не устройство).
- Новое отличие для устройства: добавьте элементу `data-ui="область-элемент"` и правило в файл уровня.
- Порядок в `index.css`: большие экраны → планшет → сенсор → телефон (правило телефона побеждает).
- Тач-цели — не меньше `--touch-target` (44 px); поле ввода на телефоне — не меньше 16 px
  (иначе iOS увеличивает страницу при фокусе).
