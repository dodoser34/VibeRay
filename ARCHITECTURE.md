## 1. Общая схема

```
┌──────────────────────────── Браузер ────────────────────────────┐
│  React (страницы, панели, формы)                                │
│     │                                                           │
│     ├── Three.js-сцена карты  ←── GSAP (камера, переходы)       │
│     │     районы (полигоны) · маркеры проблем · выбор кликом    │
│     │                                                           │
│     └── shared/api  ── fetch + JWT ──┐                          │
└──────────────────────────────────────┼──────────────────────────┘
                                       │ HTTPS, JSON, /api/v1
┌──────────────────────────────────────▼──────────────────────────┐
│  FastAPI                                                        │
│   api/v1 (роутеры) → services (логика) → models (данные)        │
│   media/ (фото проблем, аватары — без EXIF)                     │
└──────────────────────────────────────┬──────────────────────────┘
                                       │
                  База данных — ещё не выбрана
```

- Фронтенд — SPA. Карта рисуется полностью на Three.js из GeoJSON районов (без тайловых картографических сервисов).
- Бэкенд — REST API без состояния; авторизация через JWT.
- Геометрия и геозапросы (в каком районе точка, проблемы в области) — на стороне сервера. **База данных пока
  не выбрана** (выбор пользователя): модель данных ниже — логическая, без привязки к конкретной СУБД.

## 2. Маршруты фронтенда

| Путь | Страница | Назначение |
|------|----------|------------|
| `/`, `/login`, `/register` | `HomePage` | Главный экран (раздел 9.0). Путь выбирает форму панели входа (вход / регистрация); один экземпляр страницы на все три пути, поэтому форма пересобирается анимацией, а не перезагружается |
| `/map/:citySlug` | `MapPage` | 3D-карта, слои «Районы / Настроение / Проблемы» (по умолчанию «Районы»), рейтинг районов |
| `/map/:citySlug/district/:districtSlug` | `MapPage` | То же, с открытым районом (прямая ссылка) |
| `/map/:citySlug/stats?period=month\|year\|all` | `MapPage view="stats"` | Дашборд статистики города (раздел 6.4): та же 3D-карта, районы окрашены по выбранному показателю, справа — панель статистики. Вход и выход — кнопка слева внизу карты; по умолчанию период «год» |
| `/about` | `AboutPage` | О проекте |
| `/support` | `SupportPage` | Центр поддержки: поиск по ответам, категории, частые вопросы, обращение, статус сервиса |
| `/map/:citySlug/problem/:problemId` | `MapPage` | Прямая ссылка на проблему: карта открывается со слоем «Проблемы», камера летит к метке, справа — карточка с историей статусов и кнопкой «Поделиться». Выбор метки на карте тоже меняет адрес. Несуществующая проблема — панель «Проблема не найдена» |
| `/settings` | `SettingsPage` | Настройки своего профиля: публичный профиль (аватар — пресет или своё фото, никнейм, предпросмотр «как тебя видят»), «Мои сообщения» (свои проблемы со статусами, фильтр, ссылки на карту; `#settings-reports` открывает страницу сразу на них), свой район, email и смена пароля, выход и удаление аккаунта. Только для вошедших, гостя уводит на `/login`. Вход — аватар в таб-баре, на телефоне — пункт меню |

| `*` | `NotFoundPage` | 404 в стиле бумажной карты: «Этот район ещё не нанесён на карту», показывает ненайденный адрес, ведёт на карту, главную и в поддержку |

Карта не размонтируется при переходах между районами, проблемами и дашбордом — меняется только состояние, панели и положение камеры.
Переходы между страницами — через `app/transitions` (`useTransitionNavigate`, `useNavigationInterceptor`, `useTransitionReady`). По умолчанию играет переход «бумажная карта-оригами» (`shared/animations/MapFoldTransition.js`): сложенная карта вылетает из места клика и разворачивается на весь экран → страница меняется под ней, падает пин и рисуется маршрут к названию новой страницы, пока та грузится (страница держит переход через `useTransitionReady(ready)`, максимум 6 с; карта города ждёт данные города и настроений) → карта складывается и улетает к пункту таб-бара, новая страница проявляется. Если у страницы есть своя анимация выхода (главная «влетает» камерой в город), играет она. Переключение «Вход ↔ Регистрация» на главной — без перехода (это одна страница). Вступительные анимации страниц (подложка и пазл главной, 3D-город, полёт камеры и рост районов на карте, панели карты, первый экран поддержки) ждут «ворот входа» (`shared/animations/pageEntrance.js`, хук `usePageEntered`): под бумажной картой новая страница уже смонтирована и грузится, а вступление стартует в момент, когда карта начинает складываться. При прямом заходе на страницу ворота открыты сразу.

## 5.1 Данные города: Костанай

### Источник границ районов
Официального деления Костаная на административные районы нет: генплан выделяет только крупные
планировочные зоны (северная — КСК, центральная, южная — КЖБИ, их разделяют логи Костанай-сай и Абиль-сай).
Поэтому районы на карте — это **жилые районы и микрорайоны так, как их называют жители**, и строятся они
**только из OpenStreetMap** (ODbL). Названия и расположение сверены с открытыми источниками (генплан, местные СМИ).
Геометрию из 2ГИС и Google Карт не копируем.

далёкий посёлок Кунай (вне охвата карты).

### Как получаются данные
Пайплайн (Python + numpy, растр 10 м/px; скрипты пока не в репозитории):
1. **Маска города:** land use OSM (жилая, коммерческая, промышленная, ж/д, гаражи) + именованные микрорайоны + плотная
   уличная сеть (густая сетка улиц смыкается в сплошную застройку, одиночные загородные дороги отсекаются)
   → внутри административной границы «Қостанай Қ.Ә.» → минус Тобол, водоёмы и дачи. Небольшие парки и дворы
   внутри города заполняются.
   **Город без пустот и до реки:** клинья пустырей и ж/д-путей между районами закрываются (до ~700 м, у основной
   части города — до ~1,2 км; отдельно стоящий Достык не «приклеивается»), всё, что город окружает, заполняется;
   прибрежная полоса до 1,3 км дотягивается до русла Тобола (линия реки — граница, на другой берег не переходит).
   Эти добавки не делятся кварталами: их забирает ближайший район.
2. **Кварталы:** маска разрезается магистралями (trunk…tertiary), железной дорогой и рекой.
3. **Районы:** затравки — полигоны микрорайонов OSM из таблицы (для Центра и Привокзального добавлены опорные точки).
   Метки растекаются по маске города, затем **каждый квартал целиком отходит району большинства** — поэтому границы
   районов идут по реальным улицам, ж/д и реке. Квартал, где лежат полигоны двух микрорайонов без магистрали
   между ними, делится по ближайшему микрорайону.
4. **Векторизация:** граф общих границ; каждая граница упрощается (Дуглас–Пекер, 10 м) **один раз** для обоих
   соседей — между районами нет ни щелей, ни наложений. В контурах остаются «ступеньки» растра (20 м), поэтому
   фронтенд при загрузке города сглаживает их тем же способом — по общим дугам, один раз для обоих соседей
   (`shared/lib/smoothBoundaries.js`: Дуглас–Пекер 16 м + два прохода Чайкина; `getCity`). **Берега не
   сглаживаются:** рёбра, обе вершины которых лежат на контуре воды (±2 м), остаются как есть, чтобы край плитки
   совпадал с рекой и озёрами.
4a. **Вода и берега:** вода — площади OSM (`natural=water`, в т.ч. `water=river`, мультиполигоны с островами);
   где у Тобола в OSM есть только осевая линия, русло — лента 64 м по ней. Водоёмы меньше 0,3 га отброшены,
   контуры упрощены (2,5 м). Из плиток вода **вычитается** (озеро внутри района — дыра в плитке), а край
   плитки, который не доходит до реки или крупного водоёма (≥ 10 га), дотягивается до берега: берётся полоса
   «между плиткой и водой» (сумма расстояний до плитки и до воды ≤ 150 м, у посёлков — ≤ 700 м и только в их
   административной границе), спорные места делятся по ближайшему району (Вороной по точкам границ).
   Обработка разовая (Python + shapely локально, не зависимость проекта).
5. **Цвета:** раскраска графа соседства — соседние районы никогда не получают один цвет; `palette` 1–12 →
   токены `--district-1…12`. Далёкие друг от друга районы могут делить цвет.
6. `streets.geojson` — схема дорог (`backend/scripts/build_streets.py`, данные OSM через Overpass API): от магистралей до
   дворовых проездов и железная дорога. Классы схемы (`kind`): `major` (trunk/primary), `secondary`, `tertiary`,
   `local` (residential, unclassified, living_street), `service` (без парковочных рядов), `rail`. Каждая линия разрезана
   по районам — отрезок относится к району своей середины (`district`, `null` — вне районов); лёгкое упрощение
   (1,5–3 м по классу). **Названий и адресов нет** — только рисунок дорог. Скрипт пишет в обе копии данных
   (бэкенд и демо фронтенда); без сети — `--osm сохранённый_ответ.json`. `water.geojson` — вода по настоящим
   берегам: только `Polygon` (внешний контур + острова), реки — тоже площадями.
   `city.json` — центр и bbox по районам.
7. *План:* загрузить в БД через `backend/scripts/import_city.py`; проверить, что районы не перекрываются.

Лицензия ODbL — на карте обязательна подпись «© участники OpenStreetMap».

## 6. Бизнес-логика

### 6.1 Настроение района
- Пользователь ставит отметку для выбранного района. Одна **актуальная** отметка на пару «пользователь + район»: новая отметка в течение 3 часов заменяет предыдущую (защита от накрутки).
- **Текущее настроение района** считается по отметкам за последние 24 часа:
  - `score` — взвешенное среднее баллов с затуханием по времени (период полураспада 6 ч), диапазон −2…+2;
  - `dominant_mood` — самое частое настроение;
  - `distribution` — доли каждого настроения;
  - `sample_size` — число отметок.
- **Порог приватности:** если отметок меньше **5**, API возвращает `insufficient_data: true` без распределения.
- Цвет района на карте — интерполяция по `score` (шкала задаётся токенами тем `styles/themes/*.css` и дублируется в сцене).

### 6.2 Жизненный цикл проблемы
```
new ──(≥ 3 подтверждения от разных пользователей)──▶ confirmed   [автоматически]
confirmed ──(модератор)──▶ in_progress
in_progress ──(модератор)──▶ resolved
new | confirmed ──(модератор: спам, дубль, не по теме)──▶ rejected
```
- **Отклонённое сообщение** (`rejected`) видит только автор: его нет в `GET /problems`, в статистике и на карте;
  `GET /problems/{id}` для остальных — 404 `problem_not_found`, подтвердить нельзя — 409 `problem_rejected`. Автор
  получает уведомление с причиной; у дубля в карточке — ссылка на исходную (`duplicate_of`), чтобы подтвердить её.
- Автор не может подтвердить свою проблему. Подтверждение можно снять, пока статус `new`.
- Район проблемы определяется по точке; точка вне границ города — ошибка 422.
- Каждая смена статуса пишется в `problem_status_changes`.

### 6.2.1 Как житель сообщает о проблеме (интерфейс)
Кнопка «Сообщить о проблеме» (панель действий внизу карты или карточка района) → правая панель `ReportProblem`, 3 шага:
1. **Тип** — одна из 9 категорий (иконки `CategoryIcon`).
2. **Место** — клик по району на карте ставит пин (`MapScene.startPlacing`: «призрак» следует за курсором, клик — `PlacementMarker.place`, координаты через обратную проекцию). Точку можно переставить. Карта переключается на слой «Проблемы», чтобы житель увидел соседние пины и подтвердил существующую проблему вместо дубля.
3. **Подробности** — описание 10–1000 символов, до 3 фото. Перед отправкой фото **перекодируются в браузере** (`shared/lib/imageTools.js`: canvas → JPEG, ≤ 1600 px) — EXIF с геометкой и моделью телефона не покидает устройство; бэкенд всё равно удаляет EXIF повторно.

После отправки открывается карточка новой проблемы (статус «Новая») и камера подлетает к пину.

### 6.1.1 Отметка настроения (интерфейс)
Кнопка «Отметить настроение» доступна всегда (панель действий внизу карты и карточка района). В окне `MoodPicker` сначала выбирается район — заранее выбран открытый район или «свой район» из профиля, — затем одно из 7 настроений. После отметки район на карте коротко подсвечивается.

### 6.3 Статистика района
Для периода `StatsPeriod`:
- настроение за период (см. 6.1);
- число проблем по статусам;
- топ-3 категории проблем;
- динамика: настроение, число отметок и новые проблемы по интервалам — `day` → 24 часовых точки, `week` → 7 дневных, `month` → 30 дневных, `year` → 12 календарных месяцев, `all` → каждый месяц с запуска города. Интервалы выровнены по часам / суткам / календарным месяцам, последний — текущий, незаконченный. При росте нагрузки — предрасчёт или кеш (см. «Открытые вопросы»).
- **Порог приватности действует и на точки динамики:** если в интервале меньше 5 отметок, `score` точки — `null` (линия графика прерывается, число отметок видно).

**Панель района на карте** (`features/stats/DistrictPanel`, ширина 440 px) показывает эти данные и ещё то, что фронтенд считает сам из уже загруженных данных города, без отдельных запросов: место района по настроению среди районов с достаточным числом отметок, отличие от среднего по городу (порог «на уровне» — 0,1 балла), тренд за период (среднее трёх последних точек минус трёх первых), площадь района (км², по геометрии OSM — `multiPolygonAreaKm2` в `shared/lib/geoProjection.js`), доли всех 7 настроений, разбивку проблем по статусам и долю каждой категории.

### 6.4 Статистика города (дашборд)
`GET /cities/{slug}/stats?period=` — всё для дашборда одним запросом:
- `mood` — настроение города: среднее настроений районов с достаточным числом отметок, взвешенное по числу отметок; распределение — сумма распределений этих районов; `sample_size` — все отметки города;
- `trend` — изменение настроения за период: среднее трёх последних точек динамики минус трёх первых (точки без данных пропускаются);
- `series` — динамика города (как в 6.3): в каждой точке — взвешенное среднее районов, сумма отметок и новых проблем;
- `problems` — сообщения о проблемах **за период**: `reported`, `active` (не решены), `by_status`;
- `categories` — все категории с сообщениями за период, по убыванию;
- `districts` — строка на район: `mood` (агрегат, с порогом приватности), `trend` (или `null`, если данных мало), `problems.reported` и `problems.resolved` за период.

Фронтенд сам группирует помесячную динамику «все годы» по календарным годам (`groupByYear`). На карте дашборд
показывает показатель по районам: **настроение** — цвет по шкале настроения (−2…+2), **проблемы** — та же шкала
наоборот и относительно других районов (меньше всего сообщений — «лучший» цвет, больше всего — «худший»);
значение выводится на подписи района. Высота плиты — тот же показатель: чем лучше, тем выше (см. раздел 9).

### 7.1 Демо-режим: фронтенд без бэкенда
- Все запросы идут через `shared/api/client.js`. Пока `VITE_USE_MOCKS` не равен `false` (по умолчанию), их обслуживает фейковый API `src/demo-data/api/handler.js` прямо в браузере — с задержкой, валидацией и кодами ошибок как у настоящего API.
- **Все демо-данные — только в `frontend/src/demo-data/`** (см. `demo-data/README.md`): снимок геоданных Костаная `cities/kostanay/*` (копия `backend/data/cities/kostanay/*`), демо-пользователи `accounts.json`, демо-содержимое `content.json` (описания тестовых проблем, ники, названия сервисов), генератор статистики `api/generate.js`. В компонентах, страницах и `shared/` демо-данных нет.
- Реализованы: `auth/register|login|logout`, `GET /cities/{slug}`, `GET /cities/{slug}/moods`, `GET /cities/{slug}/stats`, `GET /districts/{id}/stats`, `POST /districts/{id}/mood`, `GET /problems`, `POST /problems`, `POST /problems/{id}/confirm`, `GET /problems/{id}`, `PATCH /users/me`, `PUT /users/me/avatar`, `POST /users/me/password`, `DELETE /users/me`, `GET /users/me/problems`, `GET /users/me/notifications`, `POST /users/me/notifications/read`, `POST /support/requests`, `GET /status` (в моках все сервисы «работают»). Идентификатор района в моках = его `slug`.
- Демо-аккаунт: `demo@viberay.kz` / `demo12345`. Данные живут до перезагрузки страницы.
- История для дашборда: город «работает» с января 2023 года; ~1 100 старых сообщений о проблемах (число растёт вместе с жителями, всё старше года решено) и 64 за последний месяц. У Аэропорта за день почти нет отметок — демонстрация порога приватности.
- Сообщество в демо (`demo-data/api/community.js`): у демо-пользователя уже есть 6 сообщений разных статусов (одно — отклонённый дубль) (`accounts.json` → `reports`) с историей и уведомлениями; история статусов остальных проблем восстанавливается из текущего статуса. Когда вошедший отправляет новую проблему, «соседи» подтверждают её через ~25 и ~70 с — приходят уведомления, а на 3 подтверждениях статус становится «подтверждена». Если новое сообщение той же категории оказалось в 80 м от нерешённой проблемы, через ~40 с «модератор» отклоняет его как дубль со ссылкой на исходную.
- Язык в демо: фейковый API получает язык запроса и отдаёт названия районов, подписи сервисов и тексты демо-проблем на нём (`demo-data/api/locale.js`, `content.json` → `ru` / `kk` / `en` / `de`).
- Состояние фейкового API живёт в памяти вкладки: после перезагрузки новые отметки, проблемы и аккаунты пропадают.
- Когда появится FastAPI: `VITE_USE_MOCKS=false` в `frontend/.env`; если демо больше не нужно — удалить `src/demo-data/`, ветку демо-режима в `client.js` и подсказку демо-входа в `LoginForm.jsx`.

  без ссылок на переводы, маршрут открывает само приложение.

## 8. Авторизация и безопасность
- **Access-токен** (JWT, 15 мин) — хранится в памяти фронтенда, передаётся в `Authorization: Bearer`.
- **Refresh-токен** (30 дней) — httpOnly, Secure, SameSite=Lax cookie; в БД хранится только хеш; ротация при каждом `/auth/refresh`.
- Пароли — argon2. **Проверка надёжности** (`shared/lib/passwordStrength.js`, бэкенд повторяет те же правила): обязательно — не короче 8 символов, не из списка частых/тривиальных паролей (123456, qwerty, йцукен, «aaaaaaaa», «12345678»…), не содержит часть email и никнейм; дополнительно — строчные и заглавные буквы, цифра, спецсимвол, длина ≥ 12. Принимается уровень «Средний» и выше (все обязательные + хотя бы одно дополнительное). При регистрации пароль вводится дважды. *План для бэкенда:* проверка по базе утёкших паролей (Have I Been Pwned, k-анонимность — наружу уходят только первые 5 символов SHA-1).
- Загрузки: только JPEG/PNG/WebP, до 10 МБ, проверка по содержимому (Pillow), ресайз до 1600 px по длинной стороне, **удаление EXIF**, случайные имена файлов.
- CORS — только origin фронтенда.
- Ограничение частоты: отметки настроения и создание проблем — лимиты на пользователя (реализация — в `services`, без доп. библиотек на старте).

## 9. Карта: 3D и анимации

### 9.0 Главный экран (концепт)
По скетчу пользователя:
- **Сверху** — плавающий таб-бар из 5 кнопок: слева «Войти», «Регистрация»; по центру «Карта города» (гостевой просмотр без авторизации); справа «О проекте», «Поддержка».
- **Слева** — панель «Вход в аккаунт / Регистрация» (`AuthPanel`): при появлении форма **собирается из частей**, при переключении текущая форма разлетается на части и из них собирается другая; фон карточки плавно подстраивается под новую высоту (только transform). Переключателя «Вход / Регистрация» внутри карточки нет — режим выбирается пунктами таб-бара и ссылками под формой. Регистрация — 5 шагов: email (под полем — «что даст аккаунт») → пароль (живая проверка надёжности + повтор) → никнейм (с готовыми вариантами в один клик) → аватар → свой район; превью публичного профиля (аватар + никнейм) — с шага «Никнейм».
- **Справа** — 3D-сцена: объёмный город — районы Костаная с улицами, слегка наклонён к зрителю, реагирует на курсор.
- **Слои (по скетчу):** S-кривая — это край **переднего слоя** (`FrontLayer`): левый лист с панелью входа лежит выше, отбрасывает нейтральную тень; город лежит на нижнем слое, его край уходит за край листа.
- **Ключевой переход** — «в город»: камера опускается на город, карта становится полноэкранной `MapPage`. Запускается кнопкой «Карта города» или прокруткой вниз (ScrollTrigger, только на экранах ≥ 900 px).
- **Успешная регистрация:** карточка сжимается в пин с аватаром, пин по дуге летит к выбранному району, район мягко подсвечивается, затем тот же переход в карту — сразу на этот район.

**Реализация (сейчас):** `HeroScene` — только город (`DistrictsLayer` в группе `city`), без персонажа. Публичный интерфейс: `setCity`, `setMoods`, `flyIntoCity`, `setFlyProgress`, `highlightDistrict`, `flashDistrict`, `districtScreenPosition`.
- Оформление районов — в 3D и **без неона**: матовые приглушённые плиты с тонким светлым контуром.

### Three.js-сцена
- **Проекция:** координаты GeoJSON (lon/lat) переводятся в локальные метры относительно центра города (`shared/lib/geoProjection.js`, equirectangular с поправкой на `cos(lat)` — для масштаба одного города точности достаточно).
- **Общий рантайм:** `SceneRuntime` — рендерер, `NeutralToneMapping` (сохраняет оттенки приглушённой палитры), цикл рендера с паузой на скрытой вкладке, `ResizeObserver`, полный `dispose()`. Им пользуются и карта, и главный экран. Опция `transparent` (главный экран): прозрачный холст, сквозь пустые места сцены виден живой фон сайта.
- **Живой фон сайта** (`shared/animations/SiteBackground.js`, дизайн из Claude Design): один Canvas 2D под всеми страницами — медленно «дышащий» свет, текучие топографические изолинии (шум Перлина + marching squares), пыль, плёночное зерно, параллакс от курсора (только ≥ 900 px), клик по пустому месту — волна по изолиниям (цвет и толщина линий, без свечения). 30 fps, DPR ≤ 2, пауза на скрытой вкладке и на странице карты, при `prefers-reduced-motion` — один статичный кадр. Цвета — токены (`--bg-contour` и общие).
- **Районы:** `DistrictsLayer` — `THREE.Shape` → `ExtrudeGeometry`, матовые пастельные плиты с тремя режимами цвета: `districts` (свой цвет района), `mood` (цвет настроения) и `scores` (показатель дашборда на шкале настроения — `MapScene.setOverlay`, значение показателя появляется на подписи района); между районами — светлые границы (`Line2`, токен `--scene-district-edge`), они читаются как улицы и разделяют соседей даже одного цвета; **высота плиты — значение района на шкале −2…+2** (настроение, на дашборде — выбранный показатель): чем лучше, тем выше, район с малым числом отметок — низкий; множитель высоты — ползунок «Высота районов» в фильтрах (0 — плоская карта, до ×4, по умолчанию ×2, запоминается в `localStorage`: `viberay:map:height-scale`; `MapScene.setHeightScale` поднимает подписи и метки проблем на новые крыши); hover/выбор — подъём и подсветка. Один и тот же слой используется на главном экране и на полноэкранной карте.
- **Подписи районов:** `CSS2DRenderer`; точка подписи — «самая глубокая» точка полигона (`labelPoint`), а не центроид, иначе у вытянутых районов подпись уезжает наружу.
- **Подложка плоская (не 3D), без адресов:** `CityBackdrop` — реальные улицы OSM вокруг районов (`LineSegments`), Тобол и водоёмы по настоящим берегам с островами (`ShapeGeometry` с дырами, ниже дорог — мосты видны), мягко освещённая «земля» (`--scene-ground`).
- **Схема дорог** (`roadStyles.js`): иерархия классов — магистрали толще (LineSegments2, толщина в px × масштаб интерфейса), второстепенные тоньше, жилые улицы и дворовые проезды — тонкие линии, проезды едва видны, железная дорога — пунктир; на земле — светлее земли (`--scene-road-major`, `--scene-road`, `--scene-road-service`, `--scene-rail`), на крышах районов — тёмные линии разной прозрачности. На главной рисуются все классы, кроме дворовых проездов (город маленький).
- **Улицы на районах:** улицы OSM внутри района рисуются тонкими линиями по верху его плиты (`DistrictsLayer.addStreets`) — районы выглядят как город, а не как гладкие блоки.
- **Маркеры проблем:** два `InstancedMesh` (стержни + головки), цвет по статусу, новые пульсируют; клик → карточка проблемы (её адрес `/map/:city/problem/:id`).
- **Кластеры меток:** метки ближе 70 px на экране (× масштаб интерфейса) жадно собираются в кластер; пересчёт — только когда камера сдвинулась (не чаще 160 мс). Метки кластера слетаются в его центр и исчезают, при приближении разлетаются по местам (плавное догоняние цели, а не скачок). Значок кластера — DOM-кнопка (`ClusterLabels`, CSS2D): число и кольцо из долей статусов (`conic-gradient` по токенам статусов); клик приближает камеру. Открытая проблема в кластер не прячется; подписи районов под значками прячутся (`resolveLabelOverlaps`).
- **Время суток:** свет, фон и туман следуют часу в городе — по его часовому поясу (`city.timezone`, `shared/lib/cityTime.js`), а не посетителя; `?time=HH:MM` показывает карту в другое время. Ключевые моменты (`dayCycle.js`): ночь — тихий холодный свет, рассвет и закат — мягче и чуть теплее, день — нейтральный `--scene-light`; солнце идёт с востока на запад. Вечером и ночью на крышах загораются окна (`DistrictsLayer.addWindows`: крошечные квадраты `--scene-window`, число — по площади района и `renderQuality().detail`), изредка какое-то окно гаснет или зажигается. Подпись «Костанай · вечер, 19:40» — справа внизу (в раскладке с боковыми панелями).
- **Подсказки при первом визите** (`shared/ui/CoachMarks.jsx`): затемнение с вырезом вокруг цели (SVG-маска), вырез переезжает между шагами, карточка встаёт с той стороны, где больше места (на телефоне — у верхнего или нижнего края). Три шага: район → «Отметить настроение» → «Сообщить о проблеме» (на телефоне — кнопка «+»). Показываются один раз (`localStorage`), повторить — «Как пользоваться картой» в панели фильтров.
- **Цвета сцены** берутся из CSS-токенов через `shared/lib/cssVar.js` — одна палитра для CSS и WebGL.
- **Выбор:** `Raycaster` в `Picker.js`, события передаются в React через колбэки.
- **Камера:** перспективная, ограниченный наклон и зум; перелёт к району — `gsap.to(camera.position / target)`.
- **Производительность:** `devicePixelRatio ≤ 2`, пауза при скрытой вкладке, `dispose()` при уходе со страницы. Цель — 60 fps на десктопе, ≥ 30 fps на средних телефонах.
- **Без неона:** никакой постобработки (bloom), аддитивного смешивания, `toneMapped: false` и ярких emissive — форма читается светом (полусферический + направленный), а не свечением. Эмиссия у районов — минимальная, только для различимости в тени.
- **Размер бандла:** ~1.4 МБ (≈410 КБ gzip), в основном three.js. Разбиение на чанки — когда появятся тяжёлые страницы.

### GSAP
- **Таб-бар (при загрузке сайта):** капсула вылетает сверху (на телефоне — снизу) узкой «таблеткой» и растягивается до полной ширины (`clip-path`), по центру выпрыгивает «Карта города», из неё вылетают по две кнопки в каждую сторону — сначала ближние, потом дальние; подсветка активного пункта появляется после приземления кнопок. При `prefers-reduced-motion` — только затухание.
- **Передний слой главной — стилизованный план города:** мягко изогнутые улицы (часть кварталов объединена), проспекты, пунктирные бульвары, круглые площади, зелёные парки, точки-жители в цветах настроений, зерно; свет сверху слева и тень к S-краю (плавно появляется от начала кривой). Текстура — бесшовная плитка, нарисованная один раз на canvas (`features/hero/lib/sheetTexture.js`), повторяется SVG-паттерном; цвета из токенов.
- **Главный экран, вступление:** передний слой-подложка натекает «обратным водопадом» — из правого нижнего угла вверх влево; фронт — волнистые струи, бегущие впереди, к концу сливаются в ровный слой (SVG `clipPath`, путь пересчитывается каждый кадр только во время вступления). Затем фон карточки входа/регистрации собирается из пазл-кусочков с выступами (`shared/animations/puzzlePieces.js`), слетающихся справа снизу; после сборки швы исчезают — кусочки заменяются сплошным фоном, и дальше собираются поля формы. На узких экранах подложки нет, пазл начинается сразу. При `prefers-reduced-motion` — только проявление.
- **Главный экран:** появление заголовка (на широком экране — после подложки), прорисовка S-ленты (`stroke-dashoffset`) и бегущие по ней частицы, плавное появление города, районы растут по очереди, ScrollTrigger-скраб полёта камеры, сборка/пересборка панели входа из частей, шаги регистрации, полёт пина.
- **Карта:** перелёты камеры, «вырастание» районов при загрузке, пульсация новых маркеров, появление панелей; при переходе «карта ↔ дашборд» содержимое панелей поднимается и проявляется.
- **Графики и таблицы** (`shared/ui/charts`, `features/stats`): рисуются в реальном размере контейнера (без растянутого `viewBox`), поэтому скругления и толщины не искажаются. Линия динамики — монотонная кривая без ложных выбросов; при смене периода прорисовывается заново (`pathLength` + `strokeDashoffset`), при обновлении тех же точек — плавно перетекает; столбики растут по очереди; подсказка по наведению, касанию и стрелкам клавиатуры. Полосы (`StackedBar`, `BarList`) двигают части только `transform`: `translate` внутри скруглённой дорожки, нулевые доли не дают лишних зазоров. Числа досчитывают до нового значения (`AnimatedNumber`). Строки таблиц появляются по очереди и при сортировке или смене периода едут на новое место (`useFlipList`).
- **UI:** открытие/закрытие панелей и модалок, выбор настроения.
- **Появление блоков при прокрутке** (поддержка): `revealOnScroll` — IntersectionObserver решает, когда блок виден
  (15 % на экране), GSAP только анимирует. ScrollTrigger для этого не годится у конца страницы: его позиции
  считаются заранее, и на высоком экране или после изменения высоты страницы футер не доходил до точки старта.
  ScrollTrigger остаётся там, где анимация привязана к прокрутке (скраб, закрепление); его старт — с `clamp()`.
- **Таб-бар во время перехода** лежит над бумажной картой (`html[data-transition]`), подсветка едет к нажатой кнопке
  сразу по клику. Рамка фокуса — только при работе с клавиатуры (`html[data-input]`, `app/inputModality.js`).
- Все пресеты — `shared/animations/presets.js`; при `prefers-reduced-motion` длительности → 0 или анимация отключается.

### 9.1 Адаптивность

Подробно — `frontend/src/adaptations/README.md`. Уровни: телефон < 768, планшет 768–1199
(стоя до 1023 — карта со шторкой, лёжа — с боковой панелью), десктоп 1200–1919, Full HD 1920–2559,
2K 2560–3839, 4K ≥ 3840.

- **Масштаб больших экранов.** Все размеры интерфейса — в `rem` (токены отступов, радиусов, шрифтов,
  ширины панелей `--map-panel-*`, `--content-max`, `--touch-target`). 2K и 4K поднимают корневой шрифт
  до 20 и 28 px (при высоте экрана от 1200 и 1800 px): интерфейс растёт пропорционально и сохраняет
  композицию, а не растягивается. SVG-графики и холсты умножают пиксельные размеры на `rootScale()`.
- **Стили уровней** лежат в `adaptations/<уровень>/` и переопределяют компоненты через `data-ui`;
  медиа-запросов по ширине в модулях компонентов нет. Смена структуры — через `useViewport()`.
- **Телефон — отдельный UX.** Навигация: плавающие кнопки «логотип» и «меню» + полноэкранное меню
  (аккаунт, карта, статистика, «О проекте», поддержка). Карта на весь экран: сверху чип фильтров
  (фильтры открываются шторкой), справа «весь город» и «+» (настроение, проблема, статистика — шторкой),
  снизу `BottomSheet` с тремя положениями (свёрнута / половина / почти весь экран) — в ней рейтинг,
  район, проблема, форма сообщения и дашборд. Камера смещает центр кадра вверх на высоту шторки
  (`MapScene.setViewInset`, `camera.setViewOffset`), чтобы район не прятался под ней; пока житель ставит
  точку проблемы, шторка опускается. Модалки становятся шторками снизу. Главная: город, заголовок,
  кнопка «Открыть карту города», вход.
- **Планшеты.** Стоя (и любой портретный экран уже 1200 px, например iPad Pro 1024 × 1366) — компактная
  раскладка, как телефон, но с таб-баром сверху. Лёжа — боковая панель и фильтры в одну строку.
- **Панели по своей ширине.** Карточка района, дашборд и таблица районов используют `@container`: в узкой
  панели плитки встают 2 × 2, в таблице исчезает номер места, названия переносятся.
- **Подписи районов не налезают:** `MapScene.resolveLabelOverlaps` несколько раз в секунду проецирует подписи
  на экран; при пересечении гаснет менее важная (выбранный и наведённый район, затем больший по площади).
- **Страница не шире экрана:** `#root { overflow-x: clip }` — анимации, вылетающие сбоку (пазл карточки входа),
  не расширяют область отображения телефона.
- **Сенсор.** При `pointer: coarse` любая кнопка не меньше 44 px (`adaptations/touch/touch.css`).
- **3D и эффекты.** `renderQuality()` (`adaptations/core`): телефоны — плотность пикселей ≤ 1,5, частиц
  главной 45 %, жителей в истории 60 % (слабые — 45 %), без сглаживания на слабых; кадр WebGL не больше
  ≈ 8,3 млн пикселей (4K), живой фон — ≈ 3,7 млн (до 0,75 от плотности на 4K). Камера карты в портретной
  ориентации отъезжает дальше (`zoomFactor`), а предел дальности и туман следуют за ней; обзор
  пересчитывается при повороте экрана. Сцена истории «О проекте» в портрете отъезжает мягче
  (`1,3 / √aspect`) и поднимает центр кадра на 10 % высоты над карточками (`setViewOffset`).

### Состояние на фронтенде
- Авторизация — React Context (`features/auth/model`). Город пока один и берётся из URL.
- Серверные данные — `shared/hooks/useRequest` (ключ-строка; прошлые данные остаются на экране, пока грузятся новые) и хуки фич поверх него.
- Выбранный район / проблема — в URL (React Router), чтобы работали прямые ссылки и «назад». Дашборд и его период — тоже в URL (`/map/:city/stats?period=`); показатель на карте и выделенный в таблице район — локальное состояние страницы.

### 9.2 Языки интерфейса

- Русский (основной), казахский, английский и немецкий. Тексты — `src/texts/{ru,kk,en,de}/*.json` с одинаковыми
  ключами;
  код импортирует русские файлы (`@/texts/ru/<раздел>.json`), а `shared/lib/language.js` — **первый импорт
  `main.jsx`** — записывает значения нужного языка прямо в эти объекты, **на месте**: вложенные объекты и
  массивы остаются теми же, меняются строки. Поэтому в компонентах нет «переводчика».
- **Переводы грузятся по требованию:** русский встроен в сайт, каждый другой язык — один файл сборки
  (`shared/lib/translations/<язык>.js`, 13–16 КБ в gzip), который скачивается, только когда язык нужен: при
  открытии страницы на нём (страница рисуется после `languageReady`, `main.jsx`) или при переключении (файл
  качается, пока текст размывается). Не скачался (нет сети) — страница остаётся на прежнем языке. Новый язык:
  папка `src/texts/<код>/`, файл `translations/<код>.js` и строка в `LOADERS` (`language.js`).
- **Смена языка без перезагрузки** (`shared/animations/languageTransition.js`): самые внешние элементы с текстом
  получают метку `data-language-text`, CSS-переменная `--language-blur` плавно растёт до 8 px (текст «мылится»),
  тексты меняются (`applyLanguage`), страница перерисовывается, запросы к API повторяются на новом языке —
  переход ждёт их (до 1,2 с), чтобы названия районов не сменились уже после, — и текст проявляется. Карта,
  прокрутка, открытые панели и введённые данные остаются. При `prefers-reduced-motion` — мгновенная смена.
- Что перерисовывается: оболочка (`App`) и каждая страница подписаны на язык (`useLanguage`), их содержимое
  перерисовывается вместе с ними; `useRequest` и уведомления перезапрашивают данные; 3D-карта переименовывает
  подписи районов (`MapScene.renameLabels`), экран монитора в истории перерисовывает надписи.
- **Правила для кода:** не копировать строки текстов в константы модулей — читать при рендере; подписи в
  справочниках — геттеры (`shared/config/withLabels.js`), в списках на уровне модуля — `get label()`; элементы,
  которые SplitText разбирает на слова, получают `key={language}` (иначе React не обновит их текст); измеряющие
  ширину элементы (подсветка вкладок, переключатели периода) пересчитываются при смене языка.
- **Язык — в адресе** (для поисковиков каждая версия — отдельная страница): русский без префикса
  (`/map/kostanay`), остальные — подкаталогом (`/kk/…`, `/en/…`, `/de/…`). Роутер (`app/router.jsx`) строит одни и
  те же маршруты под каждым префиксом одной глубины, поэтому при смене языка страница не монтируется заново.
  Код работает с путями без префикса: `usePagePath()` (где мы), `useLocalizedNavigate()` и `localizePath()`
  (куда идём; `TransitionProvider` и `usePageNavigate` уже добавляют префикс сами).
- `app/useLanguageRoute.js` держит язык и адрес согласованными: переключатель меняет язык — адрес меняется на ту же
  страницу с другим префиксом (`replace`); адрес сменился (назад/вперёд, ссылка) — меняется язык. Он же ставит в
  `<head>` ссылки на переводы текущей страницы (`hreflang`, `canonical`), а `language.js` — `<html lang>` и
  описание страницы (`common.meta.description`).
- При загрузке: язык из префикса адреса; старые ссылки `?lang=` переводятся на адрес с префиксом. Адрес без префикса
  — русская версия для поисковиков, а человек попадает на свою: язык, который он сам выбирал раньше (`localStorage`),
  иначе — первый подходящий из языков его браузера (`navigator.languages`; ни один не подходит — английский). Ссылка
  с префиксом (`/en/…`) открывается как есть. Роботов (`bot`, `crawl`, `spider`, `headless`, `navigator.webdriver`)
  не перенаправляем: поисковик должен видеть по каждому адресу ровно ту версию, что в нём указана.
- Переключатель `shared/ui/LanguageSwitch` — **флаги главной страны языка** (русский — Россия, казахский —
  Казахстан, английский — Великобритания, локаль en-GB, немецкий — Германия; `shared/ui/flags/*.svg` — квадратные, нарисованы под кружок: у Британии диагонали из углов, у Казахстана солнце и беркут по центру, орнамент у древка опущен), невыбранный
  флаг приглушён: в шапке справа (рядом с колокольчиком; на планшетах вкладки тогда — короткими подписями, а на
  планшете стоя виден только флаг текущего языка — нажатие раскрывает остальные), внизу меню телефона и в
  настройках (раздел «Аккаунт»: флаг и название языка на самом языке).
- Даты и числа — `Intl` с локалью текущего языка (`ru-RU` / `kk-KZ` / `en-GB` / `de-DE`, форматтеры кешируются по
  локали), склонения — `plural()` по `Intl.PluralRules` (русские три формы; в английском и немецком 1 — первая
  форма, остальное — третья; в казахском после числа слово не меняется — во всех трёх местах одно слово).
- Корешки книг в 3D-комнате читаются снизу вверх (русский, казахский, немецкий) или сверху вниз (английский).
- Шрифты (Unbounded, Manrope) подгружают расширенную кириллицу — казахские ә ғ қ ң ө ұ ү һ і рисуются ими же.
- Запросы к API идут с `Accept-Language`; сервер (и демо-API) отдаёт названия районов и свои подписи на языке
  запроса. В dev при нехватке ключа в файле перевода — предупреждение в консоли; сверка ключей и `{подстановок}`
  всех четырёх языков — обязательна при добавлении текста.

### 9.3 Скрываемые панели карты

На раскладке с боковыми панелями (десктоп, планшет лёжа) обе панели можно спрятать язычком у их внешнего края
(`pages/MapPage/PanelToggle.jsx`): панель уезжает за край экрана CSS-свойством `translate` (не `transform` —
тот занят анимациями GSAP; после появления панелей GSAP очищает свои стили), язычок встаёт у края. Содержимое
спрятанной панели `inert`. Левая панель запоминается спрятанной всегда, правая — если её спрятали на общем обзоре:
выбор района, проблемы, сообщение о проблеме или дашборд открывают её снова, возврат к обзору — снова прячет
(`localStorage`: `viberay:map:left-hidden`, `viberay:map:right-hidden`).

### 9.4 Темы оформления

- **Тёмная** (по умолчанию, «лесная ночь») и **светлая** («город днём», светло-зелёная — без чистого белого).
  Цветовые токены — `src/styles/themes/dark.css` (`:root, [data-theme='dark']`) и `light.css`
  (`[data-theme='light']`) с одинаковыми именами; `tokens.css` — всё, что от темы не зависит. Шкала настроения,
  цвета районов и статусов общие для обеих тем.
- Выбор: сохранённый (`localStorage`, `viberay.theme`) → системная настройка `prefers-color-scheme`. Тема ставится
  атрибутом `data-theme` на `<html>` до отрисовки (`shared/lib/theme.js` импортируется в `main.jsx` сразу после
  языка), меняется и цвет полосы браузера (`meta theme-color`).
- Смена на лету (`shared/animations/themeTransition.js`): страница плавно растворяется в новую через View
  Transitions (0,6 с; без API или при reduced motion — сразу). CSS перекрашивается сам; кеш `cssVar()` сбрасывается,
  а всё, что рисует цветами токенов, подписано и перекрашивается на месте: 3D-карта (`MapScene.refreshTheme` — свет,
  фон и туман, земля с дорогами и водой, плиты, границы, улицы, окна), город на главной (`HeroScene.refreshTheme`),
  текстура переднего листа, живой фон сайта (`SiteBackground.refreshTheme`), бумажная карта перехода
  (`MapFoldTransition.refreshTheme`). Камера, выбор и слои не сбрасываются.
- Переключатель `shared/ui/ThemeSwitch` (солнце / луна): в шапке рядом с языком (на планшете стоя — у логотипа),
  внизу меню телефона и в настройках (раздел «Аккаунт»). В светлой теме под логотипом — стеклянная плашка, чтобы он
  читался над тёмными блоками.
- **История «О проекте»: одна комната — ночь и день.** Модель одна (`public/models/story-room_street.glb`), у тем
  отличаются только цвета (токены `--story-*` в обеих темах), свет и тени: тёмная — июльская ночь, светлая — тот же
  день (`isDaylight()` в `features/story/content.js`; свои подписи времени и первой главы — `story.daylight` в
  `texts/{ru,en}/about.json`). Смена темы на странице пересоздаёт сцену и шкалу, кадр истории сохраняется.
  - **Свет** (`RoomSet`, по примеру интерьерных сцен Three.js): солнце (днём) или луна (ночью) — направленный свет
    через проём окна с картой теней PCF, плотно охватывающей комнату (стена с проёмом и откосами отбрасывает тень,
    поэтому свет ложится пятнами с тенями переплёта и предметов); заполняющий свет неба; слабое окружение
    `RoomEnvironment` для материалов; монитор — прямоугольный источник `RectAreaLight`; ночью — прожектор
    настольной лампы с тенью, экран телефона и подсветка внутри системного блока. Ночью горят окна домов, фонари и
    лампа — ровным цветом, без свечения. Размер карты теней — по `renderQuality()`.
  - **Комната:** системный блок под столом со стеклянной панелью (плата, водоблок со шлангами и радиатором,
    видеокарта, память, вентиляторы с кольцами подсветки, оплётки кабелей; корпус белый днём, графитовый ночью);
    полка с мангой «Атака на титанов» и книгами Стивена Кинга (корешки рисуются в `roomTextures`, тексты —
    `room.shelf`, русские читаются снизу вверх); телефон, который ночью показывает время (`room.phone`).
  - **За окном** — уменьшенная улица (масштаб 0,55, видно больше домов и неба): двор, дорога с разметкой и
    «зеброй», машины, фонари, тополя, берёзы и карагачи, пятиэтажки с балконами, девятиэтажки, силуэты, небо
    (`skyTexture`, UV плоскости покрывают только видимую из окна часть). Улица обрезана до того, что видно из окна;
    тень не отбрасывает. Туман в комнате ближе (дымка на дальних домах), над городом — прежний.
  - **Камера:** общий план комнаты шире (50°), к нырку в монитор угол сужается до 38°, чтобы карта на экране
    совпала с первым кадром города.
  - **Загрузка:** `StoryScene.ready` — модель загружена, шейдеры скомпилированы заранее (`compileAsync`, первый
    кадр без рывка) и первый кадр отрисован. Пока комната не готова, `AboutPage` держит переход между страницами
    (`useTransitionReady`, «бумажная карта» остаётся на экране; предел `HOLD_LIMIT` — 15 с), а при прямом входе
    на страницу сцену закрывает завеса цвета фона, которая растворяется после готовности.
  - Исходники — `BLENDER/Scene_room_street.blend` и скрипты генерации `BLENDER/build_street.py`,
    `build_details.py` (локально, папка в `.gitignore`).

### 9.5 Производительность и лёгкая графика

- **Сборка** (`vite.config.js`): three.js, React (+ роутер) и GSAP — отдельными файлами (`codeSplitting.groups`),
  они меняются редко и остаются в кэше браузера между обновлениями сайта. Страницы ленивые (`router.jsx`, `lazy`):
  «Поддержка» и «Настройки» не качают three.js; переход ждёт загрузки страницы (`await navigate`), пока экран
  закрыт «бумажной картой». После загрузки, когда браузер свободен, остальные страницы подгружаются фоном
  (`prefetchPages`) — но не на медленной сети и не в лёгком режиме. В `package.json` перечислены модули с побочными
  эффектами (`sideEffects`: стили, язык, тема, регистрация плагинов GSAP) — сборщик выкидывает неиспользуемые
  реэкспорты, поэтому `useCityData` из `features/map` не тянет за собой 3D-сцену.
- **3D-сцены грузятся отдельно:** `StoryScene` («О проекте») и `HeroScene` (главная) — динамическим импортом,
  вместе с three.js; модель комнаты — только в полном режиме.
- **Режим графики** (`adaptations/core/graphicsMode.js`): «авто», «полная» или «лёгкая» — выбор в настройках
  (раздел «Аккаунт», `OptionGroup`), хранится в `localStorage` (`viberay.graphics`). В «авто» лёгкая графика
  включается сама при экономии трафика или медленной сети (`navigator.connection`: 2G/3G), при памяти ≤ 2 ГБ или
  ≤ 2 ядрах, без WebGL2, а также если сцена упала или 3D-комната не загрузилась за 12 с (`fallBackToLite`, до
  перезагрузки). Компоненты узнают режим через `useLiteGraphics()`.
- **Лёгкая графика вместо сцен:** история «О проекте» — `StoryIllustration` (плоская комната на токенах темы — день и
  ночь меняются сами — и 2D-карта Костаная) + `LiteStage` с тем же интерфейсом, что у 3D-сцены (`ready`, `setCity`,
  `buildTimeline`, `dispose`), поэтому подписи, карточки и шкала прокрутки общие. Наезд на монитор `LiteStage` считает
  по размеру экрана (окно с вопросом целиком в кадре и на телефоне стоя), шкала перестраивается при повороте экрана
  или смене уровня (`useViewport().portrait`, `tier`); на компактных экранах 2D-карта стоит над карточкой настроения
  (`data-ui="story-lite-map"`, `adaptations/tablet/about.css`); герой главной — `HeroMap` (2D-карта
  с цветами настроения, тот же интерфейс, что у `Hero3D`). Цвет настроения для 2D — `moodFill()` (`features/map`):
  CSS `color-mix` соседних токенов шкалы, без three.js. Карта города (`/map`) остаётся 3D — это основная функция; на
  слабых устройствах её облегчает `renderQuality()`.

## 11. Открытые вопросы
- Кто переводит проблемы в `in_progress` и `resolved`: только модераторы или также представители акимата (отдельная роль)?
- Показывать автора проблемы или разрешить анонимную публикацию.
- **База данных** — ещё не выбрана; от выбора зависят драйвер, ORM, миграции и геозапросы (пакеты добавятся в
  `backend/requirements.txt` после выбора).
- Кеширование статистики (предрасчёт / Redis) — когда понадобится. Дашборд «все годы» считает помесячную динамику по всем районам — первый кандидат на кеширование.
- **Динамика «за день» и приватность:** почасовые точки с малым числом отметок скрываются (порог 5, раздел 6.3). В районе с 40–50 отметками в день большинство часов окажется пустым — возможно, для «дня» нужны интервалы по 3 часа.
- **«Решено за 30 дней» на карте:** в моках «актуальность» решённой проблемы считается по дате сообщения; на бэкенде — брать дату перехода в `resolved` из `problem_status_changes`.
- Хранилище фото в продакшене (локальный диск / S3-совместимое).
- Хостинг и деплой.
- Размер данных улиц: `streets.geojson` ≈ 550 КБ — когда появится бэкенд, отдавать отдельным запросом или упрощать.
- Модерация новых проблем (спам, дубли рядом) и лимит частоты сообщений — на бэкенде.
- **Контакты поддержки:** настоящих email / Telegram пока нет — на странице поддержки только форма обращения.
- **Удаление аккаунта на бэкенде:** что показывать автором проблем удалённого пользователя (например, «Бывший житель») и как обезличивать его отметки настроения (`user_id → null` или отдельная таблица агрегатов) — решить при реализации `DELETE /users/me`.
- **Статус сервиса:** в моках всё «работает»; на бэкенде нужны настоящие проверки для `GET /status`.
