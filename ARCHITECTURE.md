# VibeRay — архитектура

Документ описывает, **как** устроен проект. Правила работы и стек — в [CLAUDE.md](CLAUDE.md).
Документ живой: при любом изменении структуры, данных, API или ключевых решений он обновляется в том же изменении.
Журнал решений — [docs/DECISIONS.md](docs/DECISIONS.md), журнал изменений — [docs/CHANGELOG.md](docs/CHANGELOG.md).

**Последнее обновление:** 2026-09-27 · **Статус:** фронтенд — главный экран, авторизация, 3D-карта, «О проекте», поддержка и переходы между страницами работают в демо-режиме на данных из `frontend/src/data` (раздел 7.1) и публикуются на GitHub Pages (7.2); бэкенда пока нет.

## 1. Общая схема

```
┌──────────────────────────── Браузер ────────────────────────────┐
│  React (страницы, панели, формы)                                │
│     │                                                           │
│     ├── Three.js-сцена карты  ←── GSAP (камера, переходы)       │
│     │     районы (полигоны) · маркеры проблем · выбор кликом    │
│     │                                                           │
│     └── shared/api  ── fetch + JWT ──┐                          │
└──────────────────────────────────────┼──────────────────────────┘
                                       │ HTTPS, JSON, /api/v1
┌──────────────────────────────────────▼──────────────────────────┐
│  FastAPI                                                        │
│   api/v1 (роутеры) → services (логика) → models (SQLAlchemy)    │
│   media/ (фото проблем, аватары — без EXIF)                     │
└──────────────────────────────────────┬──────────────────────────┘
                                       │
                         PostgreSQL 16 + PostGIS
```

- Фронтенд — SPA. Карта рисуется полностью на Three.js из GeoJSON районов (без тайловых картографических сервисов).
- Бэкенд — REST API без состояния; авторизация через JWT.
- Геометрия и геозапросы (в каком районе точка, проблемы в области) — на стороне PostGIS.

## 2. Маршруты фронтенда

| Путь | Страница | Назначение |
|------|----------|------------|
| `/`, `/login`, `/register` | `HomePage` | Главный экран (раздел 9.0). Путь выбирает форму панели входа (вход / регистрация); один экземпляр страницы на все три пути, поэтому форма пересобирается анимацией, а не перезагружается |
| `/map/:citySlug` | `MapPage` | 3D-карта, слои «Районы / Настроение / Проблемы» (по умолчанию «Районы»), рейтинг районов |
| `/map/:citySlug/district/:districtSlug` | `MapPage` | То же, с открытым районом (прямая ссылка) |
| `/map/:citySlug/stats?period=month\|year\|all` | `MapPage view="stats"` | Дашборд статистики города (раздел 6.4): та же 3D-карта, районы окрашены по выбранному показателю, справа — панель статистики. Вход и выход — кнопка слева внизу карты; по умолчанию период «год» |
| `/about` | `AboutPage` | О проекте |
| `/support` | `SupportPage` | Центр поддержки: поиск по ответам, категории, частые вопросы, обращение, статус сервиса |
| `/map/:citySlug/problem/:problemId` | — | *план:* прямая ссылка на проблему (сейчас карточка открывается без смены URL) |
| `/profile` | — | *план:* свой профиль |

Карта не размонтируется при переходах между районами, проблемами и дашбордом — меняется только состояние, панели и положение камеры.
Переходы между страницами — через `app/transitions` (`useTransitionNavigate`, `useNavigationInterceptor`, `useTransitionReady`). По умолчанию играет переход «бумажная карта-оригами» (`shared/animations/MapFoldTransition.js`): сложенная карта вылетает из места клика и разворачивается на весь экран → страница меняется под ней, падает пин и рисуется маршрут к названию новой страницы, пока та грузится (страница держит переход через `useTransitionReady(ready)`, максимум 6 с; карта города ждёт данные города и настроений) → карта складывается и улетает к пункту таб-бара, новая страница проявляется. Если у страницы есть своя анимация выхода (главная «влетает» камерой в город), играет она. Переключение «Вход ↔ Регистрация» на главной — без перехода (это одна страница). Вступительные анимации страниц (подложка и пазл главной, 3D-город, полёт камеры и рост районов на карте, панели карты, первый экран поддержки) ждут «ворот входа» (`shared/animations/pageEntrance.js`, хук `usePageEntered`): под бумажной картой новая страница уже смонтирована и грузится, а вступление стартует в момент, когда карта начинает складываться. При прямом заходе на страницу ворота открыты сразу.

## 4. Модель данных (PostgreSQL + PostGIS)

Все `id` — UUID. Все даты — `timestamptz` в UTC. Геометрия — SRID 4326.

### users
| Поле | Тип | Примечание |
|------|-----|-----------|
| id | uuid PK | |
| email | varchar, unique | **приватное** |
| password_hash | varchar | argon2 |
| nickname | varchar(24), unique | 3–24 символа, `[a-zA-Z0-9_а-яА-ЯёЁ]` |
| avatar_url | varchar, null | `preset:N` (готовый аватар) или URL загруженного |
| home_district_id | FK districts, null | «свой район» — какой район открывать на карте первым; **приватное**, не показывается никому |
| role | enum `user / moderator / admin` | |
| is_active | bool | |
| created_at | timestamptz | |

### refresh_sessions
`id`, `user_id` FK, `token_hash`, `expires_at`, `revoked_at`, `created_at` — для ротации и отзыва refresh-токенов.

### cities / districts
- **cities:** `id`, `slug` (`kostanay`), `name`, `center` Point, `bbox` Polygon.
- **districts:** `id`, `city_id` FK, `slug`, `name`, `geom` MultiPolygon (GIST-индекс).

### mood_marks
| Поле | Тип | Примечание |
|------|-----|-----------|
| id | uuid PK | |
| user_id | FK users | нужен только для дедупликации, наружу не отдаётся |
| district_id | FK districts | |
| mood | enum Mood | |
| created_at | timestamptz | индекс `(district_id, created_at)` |

### problems
| Поле | Тип | Примечание |
|------|-----|-----------|
| id | uuid PK | |
| author_id | FK users | |
| district_id | FK districts | определяется сервером по точке (`ST_Contains`) |
| category | enum ProblemCategory | |
| description | text, ≤ 1000 | |
| location | Point | GIST-индекс |
| status | enum ProblemStatus | |
| confirmations_count | int | денормализация для быстрой выдачи |
| created_at / updated_at / resolved_at | timestamptz | |

### problem_photos
`id`, `problem_id` FK, `path`, `width`, `height`, `created_at`. До **3 фото** на проблему.

### problem_confirmations
`problem_id` FK, `user_id` FK, `created_at`. PK = `(problem_id, user_id)` — один пользователь подтверждает один раз.

### problem_status_changes
`id`, `problem_id`, `from_status`, `to_status`, `changed_by` (FK users, null = система), `created_at` — история для прозрачности и статистики.

### support_requests
| Поле | Тип | Примечание |
|------|-----|-----------|
| id | uuid PK | наружу отдаётся короткий номер `number` (`S-0001`) |
| number | serial, unique | |
| user_id | FK users, null | если обращение отправлено из аккаунта; писать можно и без него |
| email | varchar | почта для ответа; **приватное**, видит только поддержка |
| topic | enum SupportTopic | |
| message | text, 10–2000 | |
| created_at | timestamptz | |

### support_attachments
`id`, `request_id` FK, `path`, `content_type`, `size`, `created_at`. До **3 файлов**: JPEG/PNG/WebP (EXIF удаляется) или PDF, каждый ≤ 10 МБ.

## 5. Перечисления (единый словарь)

Коды — источник истины в `backend/app/models/enums.py`. Фронтенд дублирует их в `frontend/src/shared/config/` вместе с подписями, цветами и иконками. **Коды должны совпадать.**

### Mood — настроение
| Код | Подпись | Балл |
|-----|---------|------|
| `excellent` | Отлично | +2 |
| `good` | Хорошо | +1 |
| `normal` | Нормально | 0 |
| `anxious` | Тревога | −1 |
| `bad` | Плохо | −1 |
| `angry` | Злость | −2 |
| `very_bad` | Очень плохо | −2 |

### ProblemCategory — категория проблемы
`garbage` (мусор) · `traffic` (пробки) · `roads` (плохие дороги) · `lighting` (освещение) · `noise` (шум) · `drunkenness` (пьянство) · `public_transport` (общественный транспорт) · `parks` (состояние парков) · `other` (другое)

### ProblemStatus — статус проблемы
`new` (новая) → `confirmed` (подтверждена) → `in_progress` (в работе) → `resolved` (решена)

### UserRole
`user` · `moderator` · `admin`

### StatsPeriod — период статистики
`day` (день) · `week` (неделя) · `month` (месяц) · `year` (год) · `all` (все годы, с запуска города).
На карте выбираются `day | week | month` (текущее настроение), на дашборде — `month | year | all`
(`shared/config/periods.js`).

### SupportTopic — тема обращения
`account` (аккаунт) · `map` (карта) · `mood` (настроение) · `problems` (проблемы) · `security` (безопасность) · `technical` (техническая проблема) · `other` (другое)

### ServiceState — состояние сервиса
`operational` (работает) · `degraded` (работает с перебоями) · `down` (не работает)

Официального деления Костаная на административные районы нет: генплан выделяет только крупные
планировочные зоны (северная — КСК, центральная, южная — КЖБИ, их разделяют логи Костанай-сай и Абиль-сай).

### Как получаются данные
Пайплайн (Python + numpy, растр 10 м/px; скрипты пока не в репозитории):
1. **Маска города:** land use OSM (жилая, коммерческая, промышленная, ж/д, гаражи) + именованные микрорайоны + плотная
   уличная сеть (густая сетка улиц смыкается в сплошную застройку, одиночные загородные дороги отсекаются)
   → внутри административной границы «Қостанай Қ.Ә.» → минус Тобол, водоёмы и дачи. Небольшие парки и дворы
   внутри города заполняются.
   **Город без пустот и до реки:** клинья пустырей и ж/д-путей между районами закрываются (до ~700 м, у основной
   части города — до ~1,2 км; отдельно стоящий Достык не «приклеивается»), всё, что город окружает, заполняется;
   прибрежная полоса до 1,3 км дотягивается до русла Тобола (линия реки — граница, на другой берег не переходит).
   Эти добавки не делятся кварталами: их забирает ближайший район.
2. **Кварталы:** маска разрезается магистралями (trunk…tertiary), железной дорогой и рекой.
3. **Районы:** затравки — полигоны микрорайонов OSM из таблицы (для Центра и Привокзального добавлены опорные точки).
   Метки растекаются по маске города, затем **каждый квартал целиком отходит району большинства** — поэтому границы
   районов идут по реальным улицам, ж/д и реке. Квартал, где лежат полигоны двух микрорайонов без магистрали
   между ними, делится по ближайшему микрорайону.
4. **Векторизация:** граф общих границ; каждая граница упрощается (Дуглас–Пекер, 10 м) **один раз** для обоих
   соседей — между районами нет ни щелей, ни наложений. В контурах остаются «ступеньки» растра (20 м), поэтому
   фронтенд при загрузке города сглаживает их тем же способом — по общим дугам, один раз для обоих соседей
   (`shared/lib/smoothBoundaries.js`: Дуглас–Пекер 16 м + два прохода Чайкина; `getCity`).
5. **Цвета:** раскраска графа соседства — соседние районы никогда не получают один цвет; `palette` 1–12 →
   токены `--district-1…12`. Далёкие друг от друга районы могут делить цвет.
6. `streets.geojson`: каждый участок улицы помечен районом, в котором лежит; `water.geojson` — реки и водоёмы.
   `city.json` — центр и bbox по районам.
7. *План:* загрузить в БД через `backend/scripts/import_city.py`; проверить, что районы не перекрываются.

Лицензия ODbL — на карте обязательна подпись «© участники OpenStreetMap».

## 6. Бизнес-логика

### 6.1 Настроение района
- Пользователь ставит отметку для выбранного района. Одна **актуальная** отметка на пару «пользователь + район»: новая отметка в течение 3 часов заменяет предыдущую (защита от накрутки).
- **Текущее настроение района** считается по отметкам за последние 24 часа:
  - `score` — взвешенное среднее баллов с затуханием по времени (период полураспада 6 ч), диапазон −2…+2;
  - `dominant_mood` — самое частое настроение;
  - `distribution` — доли каждого настроения;
  - `sample_size` — число отметок.
- **Порог приватности:** если отметок меньше **5**, API возвращает `insufficient_data: true` без распределения.
- Цвет района на карте — интерполяция по `score` (шкала задаётся токенами в `tokens.css` и дублируется в сцене).

### 6.2 Жизненный цикл проблемы
```
new ──(≥ 3 подтверждения от разных пользователей)──▶ confirmed   [автоматически]
confirmed ──(модератор)──▶ in_progress
in_progress ──(модератор)──▶ resolved
```
- Автор не может подтвердить свою проблему. Подтверждение можно снять, пока статус `new`.
- Район проблемы определяется по точке; точка вне границ города — ошибка 422.
- Каждая смена статуса пишется в `problem_status_changes`.

### 6.2.1 Как житель сообщает о проблеме (интерфейс)
Кнопка «Сообщить о проблеме» (панель действий внизу карты или карточка района) → правая панель `ReportProblem`, 3 шага:
1. **Тип** — одна из 9 категорий (иконки `CategoryIcon`).
2. **Место** — клик по району на карте ставит пин (`MapScene.startPlacing`: «призрак» следует за курсором, клик — `PlacementMarker.place`, координаты через обратную проекцию). Точку можно переставить. Карта переключается на слой «Проблемы», чтобы житель увидел соседние пины и подтвердил существующую проблему вместо дубля.
3. **Подробности** — описание 10–1000 символов, до 3 фото. Перед отправкой фото **перекодируются в браузере** (`shared/lib/imageTools.js`: canvas → JPEG, ≤ 1600 px) — EXIF с геометкой и моделью телефона не покидает устройство; бэкенд всё равно удаляет EXIF повторно.

После отправки открывается карточка новой проблемы (статус «Новая») и камера подлетает к пину.

### 6.1.1 Отметка настроения (интерфейс)
Кнопка «Отметить настроение» доступна всегда (панель действий внизу карты и карточка района). В окне `MoodPicker` сначала выбирается район — заранее выбран открытый район или «свой район» из профиля, — затем одно из 7 настроений. После отметки район на карте коротко подсвечивается.

### 6.3 Статистика района
Для периода `StatsPeriod`:
- настроение за период (см. 6.1);
- число проблем по статусам;
- топ-3 категории проблем;
- динамика: настроение, число отметок и новые проблемы по интервалам — `day` → 24 часовых точки, `week` → 7 дневных, `month` → 30 дневных, `year` → 12 календарных месяцев, `all` → каждый месяц с запуска города. Интервалы выровнены по часам / суткам / месяцам (`date_trunc`), последний — текущий, незаконченный. Считается SQL-запросами с `date_trunc`; при росте нагрузки — материализованные представления (см. «Открытые вопросы»).
- **Порог приватности действует и на точки динамики:** если в интервале меньше 5 отметок, `score` точки — `null` (линия графика прерывается, число отметок видно).

**Панель района на карте** (`features/stats/DistrictPanel`, ширина 440 px) показывает эти данные и ещё то, что фронтенд считает сам из уже загруженных данных города, без отдельных запросов: место района по настроению среди районов с достаточным числом отметок, отличие от среднего по городу (порог «на уровне» — 0,1 балла), тренд за период (среднее трёх последних точек минус трёх первых), площадь района (км², по геометрии OSM — `multiPolygonAreaKm2` в `shared/lib/geoProjection.js`), доли всех 7 настроений, разбивку проблем по статусам и долю каждой категории.

### 6.4 Статистика города (дашборд)
`GET /cities/{slug}/stats?period=` — всё для дашборда одним запросом:
- `mood` — настроение города: среднее настроений районов с достаточным числом отметок, взвешенное по числу отметок; распределение — сумма распределений этих районов; `sample_size` — все отметки города;
- `trend` — изменение настроения за период: среднее трёх последних точек динамики минус трёх первых (точки без данных пропускаются);
- `series` — динамика города (как в 6.3): в каждой точке — взвешенное среднее районов, сумма отметок и новых проблем;
- `problems` — сообщения о проблемах **за период**: `reported`, `active` (не решены), `by_status`;
- `categories` — все категории с сообщениями за период, по убыванию;
- `districts` — строка на район: `mood` (агрегат, с порогом приватности), `trend` (или `null`, если данных мало), `problems.reported` и `problems.resolved` за период.

Фронтенд сам группирует помесячную динамику «все годы» по календарным годам (`groupByYear`). На карте дашборд
показывает показатель по районам: **настроение** — цвет по шкале настроения (−2…+2), **проблемы** — та же шкала
наоборот и относительно других районов (меньше всего сообщений — «лучший» цвет, больше всего — «худший»);
значение выводится на подписи района. Высота плиты — число отметок за период.

### 7.1 Демо-режим: фронтенд без бэкенда
- Все запросы идут через `shared/api/client.js`. Пока `VITE_USE_MOCKS` не равен `false` (по умолчанию), их обслуживает фейковый API `src/data/api/handler.js` прямо в браузере — с задержкой, валидацией и кодами ошибок как у настоящего API.
- **Все демо-данные — только в `frontend/src/data/`** (см. `data/README.md`): снимок геоданных Костаная `cities/kostanay/*` (копия `backend/data/cities/kostanay/*`), демо-пользователи `accounts.json`, демо-содержимое `content.json` (описания тестовых проблем, ники, названия сервисов), генератор статистики `api/generate.js`. В компонентах, страницах и `shared/` демо-данных нет.
- Реализованы: `auth/register|login|logout`, `GET /cities/{slug}`, `GET /cities/{slug}/moods`, `GET /cities/{slug}/stats`, `GET /districts/{id}/stats`, `POST /districts/{id}/mood`, `GET /problems`, `POST /problems`, `POST /problems/{id}/confirm`, `POST /support/requests`, `GET /status` (в моках все сервисы «работают»). Идентификатор района в моках = его `slug`.
- Демо-аккаунт: `demo@viberay.kz` / `demo12345`. Данные живут до перезагрузки страницы.
- История для дашборда: город «работает» с января 2023 года; ~1 100 старых сообщений о проблемах (число растёт вместе с жителями, всё старше года решено) и 64 за последний месяц. У Аэропорта за день почти нет отметок — демонстрация порога приватности.
- Состояние фейкового API живёт в памяти вкладки: после перезагрузки новые отметки, проблемы и аккаунты пропадают.
- Когда появится FastAPI: `VITE_USE_MOCKS=false` в `frontend/.env`; если демо больше не нужно — удалить `src/data/`, ветку демо-режима в `client.js` и подсказку демо-входа в `LoginForm.jsx`.

### 7.2 Публикация на GitHub Pages
- Workflow `.github/workflows/deploy-pages.yml`: на каждый `push` в `main` (и вручную) — `npm ci`, `npm run lint`, `npm run build`, публикация `frontend/dist` через `actions/deploy-pages`. В настройках репозитория: Settings → Pages → Source: **GitHub Actions**.
- Сайт работает в демо-режиме (7.1), бэкенд и `localhost` не нужны.
- Pages открывает сайт в подпапке `/<репозиторий>/`: workflow передаёт её в `VITE_BASE` (`vite.config.js` → `base`), роутер получает её как `basename` (`import.meta.env.BASE_URL`), файлы из `public/` адресуются через `BASE_URL`. Внутренние ссылки — только `Link` / `navigate` из React Router, без `<a href="/...">` и `window.location`.
- Прямые ссылки на маршруты (`/map/kostanay`, `/about`): Pages отдаёт `404.html`, а это копия `index.html` — маршрут открывает само приложение.

## 8. Авторизация и безопасность
- **Access-токен** (JWT, 15 мин) — хранится в памяти фронтенда, передаётся в `Authorization: Bearer`.
- **Refresh-токен** (30 дней) — httpOnly, Secure, SameSite=Lax cookie; в БД хранится только хеш; ротация при каждом `/auth/refresh`.
- Пароли — argon2. **Проверка надёжности** (`shared/lib/passwordStrength.js`, бэкенд повторяет те же правила): обязательно — не короче 8 символов, не из списка частых/тривиальных паролей (123456, qwerty, йцукен, «aaaaaaaa», «12345678»…), не содержит часть email и никнейм; дополнительно — строчные и заглавные буквы, цифра, спецсимвол, длина ≥ 12. Принимается уровень «Средний» и выше (все обязательные + хотя бы одно дополнительное). При регистрации пароль вводится дважды. *План для бэкенда:* проверка по базе утёкших паролей (Have I Been Pwned, k-анонимность — наружу уходят только первые 5 символов SHA-1).
- Загрузки: только JPEG/PNG/WebP, до 10 МБ, проверка по содержимому (Pillow), ресайз до 1600 px по длинной стороне, **удаление EXIF**, случайные имена файлов.
- CORS — только origin фронтенда.
- Ограничение частоты: отметки настроения и создание проблем — лимиты на пользователя (реализация — в `services`, без доп. библиотек на старте).

## 9. Карта: 3D и анимации

### 9.0 Главный экран (концепт)
По скетчу пользователя:
- **Сверху** — плавающий таб-бар из 5 кнопок: слева «Войти», «Регистрация»; по центру «Карта города» (гостевой просмотр без авторизации); справа «О проекте», «Поддержка».
- **Слева** — панель «Вход в аккаунт / Регистрация» (`AuthPanel`): при появлении форма **собирается из частей**, при переключении текущая форма разлетается на части и из них собирается другая; фон карточки плавно подстраивается под новую высоту (только transform). Переключателя «Вход / Регистрация» внутри карточки нет — режим выбирается пунктами таб-бара и ссылками под формой. Регистрация — 5 шагов: email (под полем — «что даст аккаунт») → пароль (живая проверка надёжности + повтор) → никнейм (с готовыми вариантами в один клик) → аватар → свой район; превью публичного профиля (аватар + никнейм) — с шага «Никнейм».
- **Справа** — 3D-сцена: объёмный город — районы Костаная с улицами, слегка наклонён к зрителю, реагирует на курсор.
- **Слои (по скетчу):** S-кривая — это край **переднего слоя** (`FrontLayer`): левый лист с панелью входа лежит выше, отбрасывает нейтральную тень; город лежит на нижнем слое, его край уходит за край листа.
- **Ключевой переход** — «в город»: камера опускается на город, карта становится полноэкранной `MapPage`. Запускается кнопкой «Карта города» или прокруткой вниз (ScrollTrigger, только на экранах ≥ 900 px).
- **Успешная регистрация:** карточка сжимается в пин с аватаром, пин по дуге летит к выбранному району, район мягко подсвечивается, затем тот же переход в карту — сразу на этот район.

**Реализация (сейчас):** `HeroScene` — только город (`DistrictsLayer` в группе `city`), без персонажа. Публичный интерфейс: `setCity`, `setMoods`, `flyIntoCity`, `setFlyProgress`, `highlightDistrict`, `flashDistrict`, `districtScreenPosition`.
- Оформление районов — в 3D и **без неона**: матовые приглушённые плиты с тонким светлым контуром.

### Three.js-сцена
- **Проекция:** координаты GeoJSON (lon/lat) переводятся в локальные метры относительно центра города (`shared/lib/geoProjection.js`, equirectangular с поправкой на `cos(lat)` — для масштаба одного города точности достаточно).
- **Общий рантайм:** `SceneRuntime` — рендерер, `NeutralToneMapping` (сохраняет оттенки приглушённой палитры), цикл рендера с паузой на скрытой вкладке, `ResizeObserver`, полный `dispose()`. Им пользуются и карта, и главный экран. Опция `transparent` (главный экран): прозрачный холст, сквозь пустые места сцены виден живой фон сайта.
- **Живой фон сайта** (`shared/animations/SiteBackground.js`, дизайн из Claude Design): один Canvas 2D под всеми страницами — медленно «дышащий» свет, текучие топографические изолинии (шум Перлина + marching squares), пыль, плёночное зерно, параллакс от курсора (только ≥ 900 px), клик по пустому месту — волна по изолиниям (цвет и толщина линий, без свечения). 30 fps, DPR ≤ 2, пауза на скрытой вкладке и на странице карты, при `prefers-reduced-motion` — один статичный кадр. Цвета — токены (`--bg-contour` и общие).
- **Районы:** `DistrictsLayer` — `THREE.Shape` → `ExtrudeGeometry`, матовые пастельные плиты с тремя режимами цвета: `districts` (свой цвет района), `mood` (цвет настроения) и `scores` (показатель дашборда на шкале настроения — `MapScene.setOverlay`, значение показателя появляется на подписи района); между районами — светлые границы (`Line2`, токен `--scene-district-edge`), они читаются как улицы и разделяют соседей даже одного цвета; высота плиты зависит от числа отметок; hover/выбор — подъём и подсветка. Один и тот же слой используется на главном экране и на полноэкранной карте.
- **Подписи районов:** `CSS2DRenderer`; точка подписи — «самая глубокая» точка полигона (`labelPoint`), а не центроид, иначе у вытянутых районов подпись уезжает наружу.
- **Фон:** `CityBackdrop` — реальные улицы OSM вокруг районов (`LineSegments`), Тобол (плоские ленты по линиям OSM) и водоёмы (`ShapeGeometry`), мягко освещённая «земля» (`--scene-ground`).
- **Улицы на районах:** улицы OSM внутри района рисуются тонкими линиями по верху его плиты (`DistrictsLayer.addStreets`) — районы выглядят как город, а не как гладкие блоки.
- **Маркеры проблем:** два `InstancedMesh` (стержни + головки), цвет по статусу, новые пульсируют; клик → карточка проблемы.
- **Цвета сцены** берутся из CSS-токенов через `shared/lib/cssVar.js` — одна палитра для CSS и WebGL.
- **Выбор:** `Raycaster` в `Picker.js`, события передаются в React через колбэки.
- **Камера:** перспективная, ограниченный наклон и зум; перелёт к району — `gsap.to(camera.position / target)`.
- **Производительность:** `devicePixelRatio ≤ 2`, пауза при скрытой вкладке, `dispose()` при уходе со страницы. Цель — 60 fps на десктопе, ≥ 30 fps на средних телефонах.
- **Без неона:** никакой постобработки (bloom), аддитивного смешивания, `toneMapped: false` и ярких emissive — форма читается светом (полусферический + направленный), а не свечением. Эмиссия у районов — минимальная, только для различимости в тени.
- **Размер бандла:** ~1.4 МБ (≈410 КБ gzip), в основном three.js. Разбиение на чанки — когда появятся тяжёлые страницы.

### GSAP
- **Таб-бар (при загрузке сайта):** капсула вылетает сверху (на телефоне — снизу) узкой «таблеткой» и растягивается до полной ширины (`clip-path`), по центру выпрыгивает «Карта города», из неё вылетают по две кнопки в каждую сторону — сначала ближние, потом дальние; подсветка активного пункта появляется после приземления кнопок. При `prefers-reduced-motion` — только затухание.
- **Передний слой главной — стилизованный план города:** мягко изогнутые улицы (часть кварталов объединена), проспекты, пунктирные бульвары, круглые площади, зелёные парки, точки-жители в цветах настроений, зерно; свет сверху слева и тень к S-краю (плавно появляется от начала кривой). Текстура — бесшовная плитка, нарисованная один раз на canvas (`features/hero/lib/sheetTexture.js`), повторяется SVG-паттерном; цвета из токенов.
- **Главный экран, вступление:** передний слой-подложка натекает «обратным водопадом» — из правого нижнего угла вверх влево; фронт — волнистые струи, бегущие впереди, к концу сливаются в ровный слой (SVG `clipPath`, путь пересчитывается каждый кадр только во время вступления). Затем фон карточки входа/регистрации собирается из пазл-кусочков с выступами (`shared/animations/puzzlePieces.js`), слетающихся справа снизу; после сборки швы исчезают — кусочки заменяются сплошным фоном, и дальше собираются поля формы. На узких экранах подложки нет, пазл начинается сразу. При `prefers-reduced-motion` — только проявление.
- **Главный экран:** появление заголовка (на широком экране — после подложки), прорисовка S-ленты (`stroke-dashoffset`) и бегущие по ней частицы, плавное появление города, районы растут по очереди, ScrollTrigger-скраб полёта камеры, сборка/пересборка панели входа из частей, шаги регистрации, полёт пина.
- **Карта:** перелёты камеры, «вырастание» районов при загрузке, пульсация новых маркеров, появление панелей; при переходе «карта ↔ дашборд» содержимое панелей поднимается и проявляется.
- **Графики и таблицы** (`shared/ui/charts`, `features/stats`): рисуются в реальном размере контейнера (без растянутого `viewBox`), поэтому скругления и толщины не искажаются. Линия динамики — монотонная кривая без ложных выбросов; при смене периода прорисовывается заново (`pathLength` + `strokeDashoffset`), при обновлении тех же точек — плавно перетекает; столбики растут по очереди; подсказка по наведению, касанию и стрелкам клавиатуры. Полосы (`StackedBar`, `BarList`) двигают части только `transform`: `translate` внутри скруглённой дорожки, нулевые доли не дают лишних зазоров. Числа досчитывают до нового значения (`AnimatedNumber`). Строки таблиц появляются по очереди и при сортировке или смене периода едут на новое место (`useFlipList`).
- **UI:** открытие/закрытие панелей и модалок, выбор настроения.
- **Появление блоков при прокрутке** (поддержка): `revealOnScroll` — IntersectionObserver решает, когда блок виден
  (15 % на экране), GSAP только анимирует. ScrollTrigger для этого не годится у конца страницы: его позиции
  считаются заранее, и на высоком экране или после изменения высоты страницы футер не доходил до точки старта.
  ScrollTrigger остаётся там, где анимация привязана к прокрутке (скраб, закрепление); его старт — с `clamp()`.
- **Таб-бар во время перехода** лежит над бумажной картой (`html[data-transition]`), подсветка едет к нажатой кнопке
  сразу по клику. Рамка фокуса — только при работе с клавиатуры (`html[data-input]`, `app/inputModality.js`).
- Все пресеты — `shared/animations/presets.js`; при `prefers-reduced-motion` длительности → 0 или анимация отключается.

### 9.1 Адаптивность

Подробно — `frontend/src/adaptations/README.md`. Уровни: телефон < 768, планшет 768–1199
(стоя до 1023 — карта со шторкой, лёжа — с боковой панелью), десктоп 1200–1919, Full HD 1920–2559,
2K 2560–3839, 4K ≥ 3840.

- **Масштаб больших экранов.** Все размеры интерфейса — в `rem` (токены отступов, радиусов, шрифтов,
  ширины панелей `--map-panel-*`, `--content-max`, `--touch-target`). 2K и 4K поднимают корневой шрифт
  до 20 и 28 px (при высоте экрана от 1200 и 1800 px): интерфейс растёт пропорционально и сохраняет
  композицию, а не растягивается. SVG-графики и холсты умножают пиксельные размеры на `rootScale()`.
- **Стили уровней** лежат в `adaptations/<уровень>/` и переопределяют компоненты через `data-ui`;
  медиа-запросов по ширине в модулях компонентов нет. Смена структуры — через `useViewport()`.
- **Телефон — отдельный UX.** Навигация: плавающие кнопки «логотип» и «меню» + полноэкранное меню
  (аккаунт, карта, статистика, «О проекте», поддержка). Карта на весь экран: сверху чип фильтров
  (фильтры открываются шторкой), справа «весь город» и «+» (настроение, проблема, статистика — шторкой),
  снизу `BottomSheet` с тремя положениями (свёрнута / половина / почти весь экран) — в ней рейтинг,
  район, проблема, форма сообщения и дашборд. Камера смещает центр кадра вверх на высоту шторки
  (`MapScene.setViewInset`, `camera.setViewOffset`), чтобы район не прятался под ней; пока житель ставит
  точку проблемы, шторка опускается. Модалки становятся шторками снизу. Главная: город, заголовок,
  кнопка «Открыть карту города», вход.
- **Планшеты.** Стоя (и любой портретный экран уже 1200 px, например iPad Pro 1024 × 1366) — компактная
  раскладка, как телефон, но с таб-баром сверху. Лёжа — боковая панель и фильтры в одну строку.
- **Панели по своей ширине.** Карточка района, дашборд и таблица районов используют `@container`: в узкой
  панели плитки встают 2 × 2, в таблице исчезает номер места, названия переносятся.
- **Подписи районов не налезают:** `MapScene.resolveLabelOverlaps` несколько раз в секунду проецирует подписи
  на экран; при пересечении гаснет менее важная (выбранный и наведённый район, затем больший по площади).
- **Страница не шире экрана:** `#root { overflow-x: clip }` — анимации, вылетающие сбоку (пазл карточки входа),
  не расширяют область отображения телефона.
- **Сенсор.** При `pointer: coarse` любая кнопка не меньше 44 px (`adaptations/touch/touch.css`).
- **3D и эффекты.** `renderQuality()` (`adaptations/core`): телефоны — плотность пикселей ≤ 1,5, частиц
  главной 45 %, жителей в истории 60 % (слабые — 45 %), без сглаживания на слабых; кадр WebGL не больше
  ≈ 8,3 млн пикселей (4K), живой фон — ≈ 3,7 млн (до 0,75 от плотности на 4K). Камера карты в портретной
  ориентации отъезжает дальше (`zoomFactor`), а предел дальности и туман следуют за ней; обзор
  пересчитывается при повороте экрана. Сцена истории «О проекте» в портрете отъезжает мягче
  (`1,3 / √aspect`) и поднимает центр кадра на 10 % высоты над карточками (`setViewOffset`).

### Состояние на фронтенде
- Авторизация — React Context (`features/auth/model`). Город пока один и берётся из URL.
- Серверные данные — `shared/hooks/useRequest` (ключ-строка; прошлые данные остаются на экране, пока грузятся новые) и хуки фич поверх него.

## 11. Открытые вопросы
- Нужны ли 2ГИС / Google Карты на самом сайте (подложка, поиск адреса) или только как справочник при разметке. Встраивание их API противоречит решению «карта на чистом Three.js» и требует отдельного решения.
- Подложка карты: рисовать ли в 3D улицы, реку Тобол, ж/д и зелёные зоны, и откуда брать их геометрию (например, OpenStreetMap — у него открытая лицензия).
- Кто переводит проблемы в `in_progress` и `resolved`: только модераторы или также представители акимата (отдельная роль)?
- Нужен ли статус «отклонена» для модерации спама и дублей.
- Языки интерфейса: только русский или ещё казахский.
- Показывать автора проблемы или разрешить анонимную публикацию.
- Кеширование статистики (материализованные представления / Redis) — когда понадобится. Дашборд «все годы» считает помесячную динамику по всем районам — первый кандидат на кеширование.
- **Динамика «за день» и приватность:** почасовые точки с малым числом отметок скрываются (порог 5, раздел 6.3). В районе с 40–50 отметками в день большинство часов окажется пустым — возможно, для «дня» нужны интервалы по 3 часа.
- **«Решено за 30 дней» на карте:** в моках «актуальность» решённой проблемы считается по дате сообщения; на бэкенде — брать дату перехода в `resolved` из `problem_status_changes`.
- Хранилище фото в продакшене (локальный диск / S3-совместимое).
- Хостинг и деплой.
- Размер данных улиц: `streets.geojson` ≈ 550 КБ — когда появится бэкенд, отдавать отдельным запросом или упрощать.
- Модерация новых проблем (спам, дубли рядом) и лимит частоты сообщений — на бэкенде.
- **Контакты поддержки:** настоящих email / Telegram пока нет — на странице поддержки только форма обращения.
- **Удаление аккаунта:** в FAQ поддержки сказано «удалим по обращению», а в API удаления нет — подтвердить или переформулировать; нужен ли эндпоинт `DELETE /users/me`.
- **Профиль:** смены никнейма, аватара и «своего района» в интерфейсе нет (в API есть `PATCH /users/me` и `PUT /users/me/avatar`) — FAQ пока направляет в поддержку.
- **Число районов:** в тексте везде «15 районов», а в перечне CLAUDE.md 14 названий и счётчик на «О проекте» (из данных) показывает 14 — сверить данные и тексты.
- **Статус сервиса:** в моках всё «работает»; на бэкенде нужны настоящие проверки для `GET /status`.
